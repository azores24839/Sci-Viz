# 来源主体网站发现与补漏规范

## 目的

为任意来源主体建立一份供人工浏览的候选网站清单，降低 AI 只返回单一网站、遗漏独立门户或关联网站的风险。本规范只覆盖“发现候选链接”；不执行采集、不评价网站价值、不修改 Case Hub 数据。

## 适用范围

不预设主体类别、网站栏目、域名结构、国家或语言。来源主体可拥有多个名称、多个品牌、多个域名或独立托管的网站；它们都应进入发现范围，而非只保留第一个搜索结果。

## 执行规则

1. 从主体名称、别名、历史名称、品牌名称和已知网址开始。
2. 通过多个独立路径重复检索：名称变体、已知网址、检索中发现的关联名称，以及候选网站公开链接指向的相关网站。
3. 每轮发现后整理候选网址，再至少进行一轮补漏检索；只有补漏轮未发现实质新网站时，才结束。
4. 以网站根地址或稳定入口地址为单位去重；保留指向同一主体的独立网站，不因域名不同而排除。
5. 对关系无法确定的网站保留为“其他待查看”，让工作人员自行打开判断；不要替工作人员做采集决定。

## 对话交付格式

默认只交付名称与可点击链接，按“核心网站”“关联主体或独立门户”“其他待查看网站”整理。不得默认输出评分、采集建议、自动化能力、页面结构或所有权证明。

工作人员在对话中自行打开链接、复制需要的地址，并在后续采集工作中使用经过人工选择的链接。

## 可选：视觉内容概况

仅在工作人员选定网站并明确要求后执行。抽样若干有内容的页面，报告每个网站的：抽样页面数、平均内容图片数、主要媒介。不得把抽样结果表述为精确的全站总量；排除图标、追踪资产、重复品牌元素和重复缩略图。

## 禁止事项

- 不因发现一个主网站就停止。
- 不按固定行业术语或固定栏目名称限制搜索范围。
- 不自动打开采集任务、不抓取图片、不写入数据库。
- 不把候选清单表述为“已经采全”或“唯一完整答案”。
