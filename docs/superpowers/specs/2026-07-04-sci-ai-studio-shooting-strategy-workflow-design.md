# Sci AI Studio「拍摄策略优先」工作流与资料收集设计

> 日期：2026-07-04  
> 状态：产品方向已确认，待拆分实施计划  
> 适用范围：`sci-viz-studio/`  
> 优先级：本文件是 Studio 默认工作流、项目理解、Case Hub 使用方式和联网资料收集的最新产品基准；与早期 MVP 文档冲突时，以本文件为准。

### 实施进度（2026-07-04）

- 01 资料输入已加入 Fast Research / Deep Research 的共享契约、持久化任务、Tavily 适配器、候选采用 API 和前端研究面板。
- Fast 使用 Tavily `basic` 检索；Deep 使用 `advanced` 检索并作为可恢复后台任务运行。
- 候选来源只有经用户选择后才进入原有网页资料解析链路。
- 未配置 `TAVILY_API_KEY` 时明确显示未配置错误，不生成 Mock 搜索结果。
- 类型检查、自动测试和生产构建通过；真实联网结果仍需配置有效 Tavily Key 后做服务实测。
- 02–07 工作流和贯穿式 Case Hub 改造尚未实施。

## 1. 产品决策

Sci AI Studio 的核心任务是：

> 帮助用户根据科研资料、项目目标、目标受众和拍摄限制，决定一个科研项目下一次应该怎么拍。

产品不再默认从“现有视觉素材做得怎么样”开始，也不把视觉资产审计、案例对标或联网调研设置为主流程阻塞项。

Studio 仍然是科研静图拍摄策划工作台。核心交付仍是科研视觉策略、静图拍摄方案、画面卡、现场执行清单和最终方案；本次调整改变的是默认入口、流程重心和资料证据如何参与决策。

## 2. 为什么调整

旧工作流为：

```text
资料输入
→ 视觉现状诊断
→ 目标与产物选择
→ 案例对标
→ 策展策略
→ 静图拍摄方案
→ AI 参考图
→ 方案输出
```

它隐含了三个不适合默认流程的前提：

1. 用户已经拥有足够多的现有视觉素材，可以进行结构或质量审计；
2. 每个项目都必须完成案例对标后才能讨论拍摄策略；
3. 只有完成较重的资料与案例研究，产品才开始提供拍摄价值。

真实用户更可能只拥有少量项目资料、一段项目描述、论文、网页或几张现场照片。他们首先需要的不是判断旧素材好不好，而是快速理解项目、确认目标，并形成下一次拍摄的策略。

因此默认流程必须从“诊断现状”转向“理解项目并制定拍摄策略”。

## 3. 新默认主流程

```text
01 资料输入
→ 02 项目理解
→ 03 目标与受众确认
→ 04 科研视觉策略
→ 05 静图拍摄方案
→ 06 画面卡与执行清单
→ 07 方案输出
```

主流程稳定、可预期，不因用户是否上传照片、Case Hub 是否可用、联网调研是否完成而改变拓扑。

### 3.1 节点定义

| 阶段 | 核心问题 | 主要负责人 | 主要输出 |
| --- | --- | --- | --- |
| 01 资料输入 | 系统目前知道什么，还需要补充什么？ | 用户 + 资料分析师 | 可追溯资料包 |
| 02 项目理解 | 这个科研项目是什么？ | 资料分析师 + 科研审校员 | 项目理解文档、信息缺口与待确认问题 |
| 03 目标与受众确认 | 这次拍摄最主要服务谁、解决什么传播任务？ | 用户 | 已确认目标、受众与基本边界 |
| 04 科研视觉策略 | 为实现目标，应该采用什么视觉表达路径？ | 科研策展人 + 科研审校员 | 科研视觉策略及案例依据 |
| 05 静图拍摄方案 | 策略如何转化为可组织的拍摄主题与场景？ | 摄影策划师 | 静图拍摄方案 |
| 06 画面卡与执行清单 | 每张图拍什么、为什么拍、怎么拍？ | 摄影策划师 + 用户 | 画面卡、优先级与现场执行项 |
| 07 方案输出 | 如何形成可沟通、可审核、可执行的交付？ | 系统 + 用户 | 最终方案、审核内容与执行版本 |

## 4. 02「项目理解」的严格边界

02 的职责是理解科研项目，不是判断如何拍摄。

### 4.1 必须输出

- 项目背景与研究方向；
- 项目试图解决的问题；
- 核心研究对象；
- 研究过程、成果形态与应用语境；
- 资料中明确出现的人物、设备、材料、样品、环境或数据对象；
- 已确认事实及对应来源；
- 已知的公开、保密、安全与现场限制；
- 当前资料能够支持的理解；
- 当前资料不能支持的判断；
- 信息缺口、矛盾信息和待确认问题。

### 4.2 明确禁止输出

- 拍摄主题；
- 视觉路线、视觉气质或风格方向；
- 可拍对象的拍摄优先级；
- 景别、机位、构图、光线和动作建议；
- 画面卡；
- 对现有视觉资产质量的判断；
- 把 Case Hub 案例当作项目事实；
- 任何未经来源支持的科研结论。

所有拍摄判断从用户完成 03「目标与受众确认」后，在 04「科研视觉策略」开始。

### 4.3 少量资料也可以进入 02

用户只有一段文字时，系统仍可生成项目理解，但必须区分：

- 资料明确支持的事实；
- 基于文本可以合理归纳的内容；
- 当前无法判断的事项；
- 建议补充的资料。

资料少不阻止用户理解项目和确认目标，但系统不能用完整、肯定的语言掩盖证据不足。

## 5. 资料输入的产品结构

资料输入是统一资料池，不只是文件上传框。

首版支持：

- PDF；
- DOCX；
- PNG / JPG；
- 粘贴文字；
- 单个公开网页链接；
- Fast Research；
- Deep Research。

本轮不加入：

- Google Drive；
- 其他云盘；
- 云端文件 OAuth；
- 登录态网页抓取；
- 自动递归抓取整个网站。

## 6. 联网资料收集入口

资料输入面板提供统一研究输入框：

> 输入研究主题、项目名称、实验室名称，或希望补充的问题

输入框旁提供研究模式选择：

- `Fast Research`：快速获得公开来源；
- `Deep Research`：获得更完整的异步来源报告。

二者都是资料收集方式，不是新的主流程节点，也不直接生成拍摄策略。

## 7. Fast Research

### 7.1 产品目的

帮助用户快速补充项目背景和公开事实，适合：

- 查找项目或实验室官网；
- 查找研究方向简介；
- 查找公开论文、机构新闻或成果页面；
- 快速确认名词、设备或项目背景；
- 为 02 项目理解补充少量权威来源。

### 7.2 建议输出

- 5–10 个公开来源；
- 标题；
- URL 与域名；
- 发布者或机构；
- 发布时间，无法确认时明确标记；
- 来源类型，如官网、论文、新闻、机构介绍；
- 简短摘要；
- 与当前检索问题的相关性说明；
- 抓取或访问时间；
- 无法读取、登录限制或内容失效状态。

### 7.3 用户控制

- 搜索结果先进入候选区；
- 用户勾选后才进入项目资料池；
- 未采用结果不应进入 Agent 的正式上下文；
- 用户可以单独打开原始来源；
- 用户可以删除已加入资料池的搜索来源；
- 加入资料池后，来源使用与现有网页资料相同的解析、选择和引用规则。

### 7.4 不做什么

- 不直接生成项目理解结论；
- 不把搜索摘要当成已经确认的项目事实；
- 不自动启动拍摄策略；
- 不自动把所有搜索结果加入项目；
- 不因为搜索无结果而阻止主流程。

## 8. Deep Research

### 8.1 产品目的

Deep Research 用于复杂项目、资料明显不足或用户希望获得更系统公开背景时，补充：

- 多来源项目背景；
- 关键研究方向与术语；
- 机构、项目、论文和公开成果之间的关系；
- 不同来源的一致信息与矛盾信息；
- 仍需用户或科研人员确认的问题。

### 8.2 异步任务

- 用户主动启动；
- 以后台任务运行；
- 显示排队、运行、完成、失败和可重试状态；
- 用户可以离开资料输入区并继续主流程；
- 不锁定 02 或后续节点；
- 完成后通过项目内通知提示；
- 刷新或重新登录后任务状态仍可恢复。

### 8.3 建议输出

- 结构化研究报告；
- 关键发现；
- 来源列表与逐条引用；
- 来源类型和可信性提示；
- 矛盾信息；
- 信息缺口；
- 待确认问题；
- 报告生成时间和研究查询；
- 检索范围或覆盖局限。

报告和来源作为一组候选资料呈现。用户确认采用后才加入项目资料包。

### 8.4 后到结果的处理

如果用户已经完成 02 或进入后续阶段，Deep Research 完成时：

1. 不自动覆盖任何现有产物；
2. 显示“发现了新的公开资料”；
3. 说明新资料可能影响哪些事实、缺口或后续策略；
4. 用户选择采用后，将资料加入项目；
5. 用户决定是否重新生成 02 项目理解；
6. 重新生成必须创建新版本；
7. 已完成的策略和方案只提示可能过期，不被静默修改。

## 9. 网络来源的证据规则

- 每条网络资料必须保存原始 URL、标题、发布者、访问时间和来源类型；
- 摘要必须可回到具体来源；
- 搜索引擎摘要不能代替原网页内容；
- 官网、论文、权威机构和普通新闻应在 UI 中可区分；
- 无法确定发布时间、作者或原始出处时明确显示未知；
- 多个来源互相冲突时，进入待确认问题；
- 网络资料不能代替用户确认现场事实；
- 网络搜索不能访问私网地址、本地地址或被安全规则禁止的 URL；
- 搜索结果中的网页仍需经过现有 SSRF、重定向、大小和内容类型检查；
- 资料选择、删除、用户归属和配额规则与其他资料一致。

## 10. Case Hub：贯穿式案例证据层

Case Hub 案例对标不再是独立的强制主流程节点，但不会消失。它升级为 02–06 均可访问的“案例证据层”。

### 10.1 各阶段用途

| 阶段 | Case Hub 的作用 |
| --- | --- |
| 02 项目理解 | 提供同研究方向、同团队类型案例，帮助识别可能涉及的视觉对象；不得替代项目事实，不输出拍摄判断 |
| 03 目标与受众确认 | 用代表案例解释不同传播目标可能形成的表达差异 |
| 04 科研视觉策略 | 作为重点证据，按目标、受众、学科、对象与技术条件推荐案例并解释策略依据 |
| 05 静图拍摄方案 | 为主题、场景组织、人物与设备关系提供可借鉴案例 |
| 06 画面卡与执行清单 | 为具体画面卡绑定参考案例，说明可借鉴与不可照搬的部分 |
| 07 方案输出 | 汇总最终采用案例、来源、三轴标签、匹配层级和借鉴理由 |

### 10.2 自动建议，人工采用

- 系统可根据当前项目和阶段自动请求候选案例；
- 用户不必启动一个独立对标流程才能看到案例；
- 候选案例不自动写入正式产物；
- 用户点击“采用为参考”后，案例才进入当前策略、方案或画面卡；
- 用户可移除或替换已采用案例；
- 已采用案例保留来源、三轴标签、匹配层级、推荐理由和借鉴点；
- 一个案例可以服务多个阶段，但每处应记录具体用途；
- 04 是案例研究最集中的阶段，但其他阶段也可以查询和采用案例。

### 10.3 不再设置的阻塞规则

- 不再要求至少选择 3 个案例才能进入下一阶段；
- Case Hub 无合适结果时允许继续；
- Case Hub 暂时不可用时允许继续；
- 无案例依据应显示为证据缺口，但不等同于现场不可执行；
- Case Hub 案例只能支持视觉策略与方法依据，不能证明用户现场具备对应条件。

## 11. 可选视觉资产审计

“已有视觉资产审计”从默认项目理解中移出。

仅在以下条件下出现：

- 用户上传了已有照片或视觉资产；
- 用户主动选择“分析现有视觉素材”。

它可以分析素材结构、覆盖对象、重复、明显缺口和可复用性，但：

- 不改变 02 项目理解的定义；
- 不阻塞目标确认或策略生成；
- 不要求用户为了使用 Studio 先准备现有照片；
- 审计结果作为 04 科研视觉策略的可选补充输入。

## 12. 资料充足度与后续方案

资料不足时，主流程仍可继续，但输出必须说明：

- 当前资料明确支持什么；
- 当前资料暂不支持什么；
- 哪些内容是推测或建议；
- 哪些事实、现场条件或限制尚待确认。

联网研究和 Case Hub 可以提高项目理解与策略依据，但不能替代：

- 目标和受众确认；
- 实际拍摄对象确认；
- 场地、人物、设备和时间确认；
- 保密、安全与公开边界确认。

## 13. Agent 职责调整

### 资料分析师

- 管理资料输入；
- 读取用户资料与被采用的网络资料；
- 生成 02 项目理解；
- 区分事实、归纳、未知和待确认；
- 不再默认执行视觉资产结构诊断；
- 不提出拍摄方向。

### 科研审校员

- 检查项目理解中的事实与来源；
- 标记矛盾、保密、安全和公开问题；
- 检查网络研究是否把推测写成事实；
- 在策略与方案阶段继续承担贯穿式风险检查。

### 科研策展人

- 从 04 开始提出视觉策略；
- 综合目标、受众、项目理解和被采用的 Case Hub 案例；
- 解释策略与案例之间的关系；
- 不把网络搜索或案例内容误写为用户项目事实。

### 摄影策划师

- 将 04 策略转成 05 方案和 06 画面卡；
- 使用被采用的案例作为具体参考；
- 仍须遵守现场与科研风险边界。

## 14. UI 信息架构

### 14.1 资料输入区

建议包含：

1. 统一输入区：上传、粘贴文字、网页链接；
2. 联网研究输入框；
3. 模式选择菜单：Fast Research / Deep Research；
4. 研究任务状态；
5. 搜索候选结果；
6. 已加入项目资料；
7. 资料选择与解析状态；
8. 资料数量、失败和配额提示。

不出现云端硬盘入口。

### 14.2 Case Hub 入口

Case Hub 不作为主流程中的单独大节点。建议在 02–06 的右侧上下文面板中提供一致的“案例依据”区域：

- 自动候选；
- 当前阶段筛选说明；
- 已采用案例；
- 查看来源；
- 采用、移除和替换；
- 匹配不足或服务不可用状态。

## 15. 数据与版本原则

- Fast Research 与 Deep Research 都应有独立任务记录；
- 记录查询、模式、状态、用户、项目、创建时间和结果；
- Deep Research 结果可在刷新和重启后恢复；
- 搜索候选与正式 `SourceDocument` 分开；
- 只有用户采用的结果才创建或进入正式资料记录；
- 采用新资料后，不自动改写已确认产物；
- 重新生成项目理解、策略或方案时创建新版本；
- Case Hub 的候选、采用关系和使用阶段应持久化；
- 所有资源继续执行用户与项目隔离。

## 16. 错误与降级

### Fast Research

- 无结果：提示调整查询，不影响资料池；
- 部分网页失败：保留成功来源并逐条显示失败；
- 服务限流：提供稍后重试；
- 查询过宽：提示用户补充项目、机构或研究对象。

### Deep Research

- 任务运行较久：持续显示后台状态，不阻塞工作；
- 失败：保留查询与失败原因，允许重试；
- 部分完成：报告明确覆盖不足，不伪装完整；
- 配额不足：不创建假任务，说明恢复条件。

### Case Hub

- 无精确案例：展示相关或跨领域案例及降级原因；
- 无任何案例：允许继续并显示证据缺口；
- 服务不可用：保留项目上下文，允许稍后刷新；
- 图片失效：保留标题、来源、标签和推荐理由。

## 17. 验收标准

### 产品流程

- 新项目默认显示七步主流程；
- 不再出现强制“视觉现状诊断”节点；
- 不再出现强制“案例对标”节点；
- 02 不产生拍摄建议；
- 04 才首次产生拍摄相关视觉策略；
- 只有一段文字也能完成 02 并进入 03。

### 资料收集

- 用户可以在资料输入中选择 Fast Research 或 Deep Research；
- 页面不出现 Google Drive 或其他云盘入口；
- Fast Research 候选由用户选择后才进入资料池；
- Deep Research 在后台运行且不阻塞主流程；
- Deep Research 完成后不会自动覆盖既有产物；
- 所有采用的网络资料可追溯到原始来源。

### Case Hub

- 02–06 均可查看阶段相关的候选案例；
- 用户采用后案例才进入正式产物；
- 04 提供最完整的策略型案例推荐；
- 没有案例或服务失败时不阻塞主流程；
- 正式采用案例显示来源、三轴、匹配层级和借鉴理由。

### 可信性

- 02 明确区分事实、归纳、未知和待确认；
- 网络摘要不被当作用户项目事实；
- Case Hub 案例不被当作用户现场条件；
- 新资料到达后由用户决定是否重新生成；
- 所有重新生成保留版本历史。

## 18. 本轮明确不做

- 云端硬盘和 OAuth；
- 无边界全网爬取；
- 自动递归抓取网站；
- 登录态或私有网页研究；
- Deep Research 自动阻塞工作流；
- 自动把全部搜索结果加入项目；
- 自动用新资料覆盖已确认产物；
- 强制选择固定数量的 Case Hub 案例；
- 恢复“视觉资产诊断优先”的默认流程；
- 在 02 生成拍摄方向、方案或画面卡。

## 19. 实施影响概览

后续实施计划至少需要覆盖：

1. 工作流模板升级与旧项目迁移；
2. 节点 ID、状态与历史产物兼容；
3. 资料分析师提示词和结构化输出调整；
4. Fast / Deep Research 任务、搜索候选和资料采用模型；
5. 资料输入 UI 与异步任务状态；
6. Case Hub 从独立节点改为贯穿式上下文能力；
7. 方案和画面卡的案例引用关系；
8. Deep Research 后到结果与版本提示；
9. 旧 Fixture、评估集、测试和帮助文案迁移；
10. 浏览器端完整流程回归。
