# Sci AI Studio 画布自愈与 Mock 隔离设计

## 背景

Studio 存在两类会破坏用户信任的问题：React Flow 偶发将节点集合重置为空，导致顶部流程和右侧面板仍可交互但画布无内容；同时，Studio 仍引用“长兴海洋实验室”fixture、初始 mock 产物和硬编码案例数据，使无资料或其他项目出现错误的长兴内容。

## 目标

1. 画布不会因 React Flow 的空 reset、视口偏移或容器尺寸变化而持续空白。
2. Studio 只使用当前项目的名称、资料和 AI 产物。
3. 无资料项目显示明确空状态，不注入 mock 资料。
4. 已持久化的旧 mock 内容可被安全识别和清理，不删除用户真实资料。

## 设计

### 项目真实数据

Studio 加载当前 `projectId` 对应的项目记录，将真实项目名称同时传入页头和 Agent draft。`changxingProject` 不再是 Studio 运行时依赖，fixture 仅允许用于测试或显式 demo。项目加载失败时显示可重试错误，不回退到长兴名称。

### 无资料初始状态

`source-intake` 初始状态只表达“请添加并选择资料”，不带 Case Hub mock 文本、数量、比例或长兴缩略图。后续节点仅消费已选且可用的 `SourceDocument` 以及真实上游产物。

### 旧 Mock 迁移

在工作流恢复时执行纯函数迁移。只匹配可确定的历史 mock 指纹，例如“Sci-Viz Case Hub mock 资料库”、固定的 126 条样本文案和旧长兴 demo 产物。命中的节点恢复为模板对应的等待状态；用户资料、无指纹的 Agent 产物和人工修订不受影响。迁移结果通过现有保存机制持久化。

### 节点展示

移除 `WorkflowNodeCard` 中对长兴图片、固定比例、mock 资料源和固定诊断的运行时引用。节点有 `artifactBody` 时渲染真实产物；没有时渲染状态摘要和空状态。案例对标节点继续使用真实 `BenchmarkPanel`。

### 画布自愈

1. 保留 `preserveWorkflowNodes`，拒绝删除模板定义的必需节点。
2. 将“定位到选中节点”封装为稳定回调。顶部流程每次点击都触发，包括重复点击当前步骤。
3. React Flow 完成初始化或容器从无尺寸恢复时，如所有必需节点均不在可见范围，自动 `fitView` 到当前节点。
4. 自愈不修改服务端工作流状态，仅恢复画布节点和视口。

## 错误处理

- 项目或工作流加载失败：保持加载/错误页，不渲染伪数据。
- 视口恢复失败：保留 React Flow 控件，下一次流程条点击再次定位。
- 旧 mock 指纹不确定：不自动清理，宁可保留也不删除用户内容。

## 测试

- React Flow 空 reset 不会删除模板节点。
- 重复点击当前流程步骤会调用节点定位。
- 切换节点和容器尺寸恢复后画布仍有可见节点。
- 新项目无资料时不含任何 Case Hub 或长兴 mock 文本。
- 页头和 Agent draft 使用当前项目名称。
- 迁移会清理已知 mock 产物，但保留真实资料和无指纹产物。
- 现有工作流持久化、资料选择和 Agent 任务测试保持通过。

## 非目标

- 不在本次修复中重新设计工作流拓扑。
- 不改变 Case Hub 的真实对标接口。
- 不自动删除整个项目、资料文档或历史版本。
