# Sci AI Studio 稳定内测工作总表

> 日期：2026-07-02  
> 目标：支持首批约 20 人、但不在产品中限制人数的可扩展稳定内测  
> 核心闭环：上传真实资料 → 四个 Agent 分析与策划 → 用户修改确认 → 导出可沟通、可执行的静图拍摄方案

## 1. 产品决策

本轮不追求一次做成可收费的完整 SaaS，而是先打通一个可被真实用户完成的端到端闭环。

内测通过标准：

1. 用户能用邮箱和密码注册登录。
2. 用户能创建多个真实项目，不再被固定在“长兴海洋实验室”演示项目。
3. 上传 PDF、Word、PNG/JPG、文字和网页后，能看到解析、OCR、摘要和失败原因。
4. 页面刷新、重新登录或服务器重启后，项目流程和产物不丢失。
5. 四个 Agent 有真实、可解释的输入输出边界，不只是四个头像或固定 Mock 文案。
6. 用户能直接编辑 Agent 结果，保存新版本并查看历史版本。
7. 系统能生成结构化画面卡、拍摄清单和最终方案。
8. 用户能导出 PDF 或 Word，并能把审核链接发给科研人员确认。
9. 管理员能看到用户、用量、失败任务和用户反馈。
10. 人数、配额和并发都由配置控制，不把 20 人写死在代码中。

## 2. 当前真实状态

### 已实现

- 固定的 React Flow 静图策划流程画布。
- 四个可见 Agent 角色、提示词和基础 DeepSeek Gateway。
- PDF、DOCX、PNG/JPG、粘贴文字和公开网页输入。
- Qwen OCR、文档/网页提取与 AI 摘要。
- 本地文件/生产 OSS 存储边界。
- 本地 JSON/生产 PostgreSQL 资料元数据边界。
- Clerk 邮箱密码登录接入、用户数据隔离和 API 限流。
- 资料、存储和每日 AI 用量配额，以及右上角额度小窗。
- ECS + OSS + PostgreSQL + Docker Compose 部署基线。
- OpenRouter AI 参考图生成接口。

### 未完成或仅为演示

- 每个用户只有一个由账号派生的默认项目 ID。
- 工作流状态、目标选择、Agent 产物主要保存在浏览器 React state 中。
- 页面刷新后，多数流程结果会回到初始演示状态。
- 长兴项目名称、大量数据占比和对标案例仍是 Fixture/Mock。
- Case Hub 尚未按用户项目真实检索并返回可追溯推荐。
- 科研审校员尚未成为诊断、策展和拍摄方案的贯穿式阻断规则。
- Agent 请求仍以同步 HTTP 为主，没有真正可恢复的后台任务队列。
- Agent 产物多为 Markdown 文本，缺少结构化 Schema、可编辑字段和引用关系。
- 没有项目列表、新建项目、方案详情、拍摄清单和外部审核页。
- 没有真正的产物版本、版本对比和恢复。
- 没有 PDF/Word 导出、管理后台、用户反馈和基础运营数据。
- 网页抓取 SSRF 防护、文件扫描、异常上传清理和自动备份演练尚未完成。

## 3. 任务分工原则

### Codex 负责

Codex 负责高风险、跨模块、需要架构判断或安全判断的任务：

- 数据库 Schema、迁移、事务和数据隔离。
- 项目、工作流、Agent Job、产物和版本的核心模型。
- 身份认证、授权、审核链接和管理员权限。
- Case Hub 与 Studio 的跨系统 API 契约。
- AI 队列、并发、幂等、超时、重试、恢复和配额记账。
- 文件、网页抓取、对象存储和导出的安全边界。
- 端到端测试、压力测试、生产环境排障和最终代码复核。

### DeepSeek 负责

DeepSeek 负责边界明确、可独立验收、失败容易发现的任务：

- 页面和组件的局部 UI 实现。
- 表单、空状态、错误文案和帮助说明。
- 已有 API 契约下的前端接入。
- 固定 Schema 下的显示组件和表单校验。
- 单元测试、Fixture、边界样例和文档。
- 用户反馈整理、日志归类、内测 FAQ 和操作教程。

DeepSeek 不得独立修改：数据库迁移、Clerk 权限、配额扣除、审核 Token、OSS 权限、SSRF 防护和生产密钥。

## 4. 里程碑与任务

## M1 项目系统与持久化（P0）

目标：用户可创建多项目，刷新页面后不丢工作。

### CX-01 项目与工作流数据模型 — Codex

交付：

- `project`、`project_workflow`、`workflow_node_state`、`artifact`、`artifact_version`、`agent_job` 的 PostgreSQL Schema 和迁移。
- 每张表包含用户归属、时间戳和必要索引。
- 本地开发与生产 PostgreSQL 使用相同契约。

验收：

- 迁移可在空数据库执行，再执行一次不会破坏数据。
- 用户 A 无法读写用户 B 的项目、节点、产物或任务。
- 项目删除行为明确：本轮使用软删除，原文件由延时清理任务处理。
- 完成 repository 和权限边界测试。

### CX-02 项目 API 与工作流状态 API — Codex

交付：

- 创建、列表、查看、重命名、归档项目 API。
- 读取与保存节点状态、目标选择和当前版本 API。
- 为现有默认项目提供一次性迁移或兼容逻辑。

验收：

- 创建 3 个项目后可分别打开，资料不串项目。
- 完成两个节点后刷新页面，进度、选择和产物保持不变。
- 用户同时打开两个标签页修改时，过期版本不会静默覆盖新版本。

### DS-01 项目列表与新建项目 UI — DeepSeek

前置：CX-02 API 契约已冻结。

交付：

- 项目列表、空状态、新建项目表单、重命名和归档交互。
- 项目字段：名称、团队类型、研究方向、主要受众、拍摄目标。
- 加载、空数据、无权限、网络失败状态。

验收：

- 窄屏 375px 和桌面 1440px 下无溢出。
- 表单不允许空名称；重复提交不创建两个项目。
- 所有按钮有加载或禁用状态，错误信息可被用户理解。
- 至少包含项目列表、创建成功、校验失败和 API 失败测试。

## M2 AI 任务与四 Agent 真实化（P0）

目标：AI 任务可在后台执行、可恢复，四个角色有真实边界。

### CX-03 Agent Job 队列 — Codex

交付：

- PostgreSQL 持久化 Job 队列，状态包含 queued/running/awaiting_human/completed/failed/cancelled。
- 幂等键、超时、有上限的重试、退避、进程恢复和错误分类。
- 按用户和全局限制并发，不写死用户数量。
- 只在真正发起模型调用时扣额度，重试记账规则明确。

验收：

- 任务运行时重启 Worker，任务最终恢复或进入明确失败状态。
- 重复点击不会生成两份相同产物。
- 模型 429、5xx、超时和输出校验失败使用不同错误码。
- 同时发起超过并发限制的任务时，多余任务排队而不丢失。

### CX-04 结构化 Agent 契约与贯穿审校 — Codex

交付：

- 资料分析师、科研审校员、科研策展人和摄影策划师的独立输入/输出 Schema。
- 每个结论的来源引用、可信度和待确认状态。
- 科研审校员在诊断、策展和拍摄方案中分别产生风险项。
- 阻断级风险未解决时，方案可预览但不可标记“可执行”。

验收：

- 缺少事实时模型不能把推测写成已确认事实。
- 每条核心结论至少有来源、“待确认”或“用户补充”三者之一。
- 输出不符合 Schema 时不写入正式产物，保留可调试失败记录。
- 阻断规则有单元测试和端到端测试。

### DS-02 Agent 状态、错误与重试 UI — DeepSeek

前置：CX-03 API 契约已冻结。

交付：

- queued、running、awaiting_human、failed、completed 的统一状态组件。
- 显示开始时间、使用资料数、当前版本和可理解错误原因。
- 可重试错误提供重试；配额不足提供恢复时间；不可重试错误不显示假重试按钮。

验收：

- 状态与 API 错误码一一对应，不通过解析错误文字推断。
- 轮询或消息更新不会重置用户正在编辑的内容。
- 键盘可操作，屏幕阅读器可读取状态变化。
- 为每种状态和至少四种错误编写组件测试。

### DS-03 Agent 提示词测试集 — DeepSeek

交付：

- 至少 20 组去敏科研项目输入，覆盖高校、医院、工程、材料、环境和企业研发。
- 每组包含预期字段、必须出现的待确认项和禁止编造项。
- 生成一份可机器执行的评估数据集。

验收：

- 数据集不含真实密钥、未公开个人信息或未经授权的内部资料。
- 四个 Agent 的样例均不少于 5 组。
- Codex 随机抽查 20% 样例，无严重角色越界。

## M3 Case Hub 真实对标（P0）

目标：对标结果来自真实案例库，可以解释为什么推荐。

### CX-05 Case Hub 读取 API 与推荐策略 — Codex

交付：

- Case Hub 专用只读 API，不允许 Studio 直连 Case Hub SQLite。
- 按团队类型、学科、传播目标和三轴标签筛选。
- 匹配分数、推荐理由、降级匹配说明和案例原始来源。

验收：

- 一次请求可返回至少 3 个对标案例，不足时返回明确降级理由。
- 每个案例包含 ID、缩略图、原始来源、三轴标签和匹配解释。
- 统计不混入 `mediaType`、`contentType` 或采集方式作为三轴结论。
- Case Hub 不可用时，Studio 保留项目上下文并允许稍后重试。

### DS-04 对标案例选择 UI — DeepSeek

前置：CX-05 API 契约已冻结。

交付：

- 案例缩略图、三轴标签、推荐理由、匹配层级和来源链接。
- 用户可选入、移除或替换案例，至少选 3 个才能进入下一阶段。
- 匹配不足和 Case Hub 不可用的独立状态。

验收：

- 用户能区分“精确匹配”和“降级参考”。
- 原始来源可打开，图片失效时有占位与文字信息。
- 选中状态刷新后保留。

## M4 方案工作区（P0）

目标：用户能修改 AI 结果，得到结构化、可执行的拍摄方案。

### CX-06 产物版本、冲突和恢复 — Codex

交付：

- 不可变的产物版本、当前版本指针和用户/Agent 修改来源。
- 保存时的乐观锁、版本冲突提示和恢复历史版本。
- 每个版本保留来源引用和风险关系。

验收：

- 所有编辑都创建新版本，不覆盖历史内容。
- 可查看版本创建时间、创建者、修改来源和摘要。
- 两个标签页同时编辑时不会静默覆盖。
- 恢复旧版本会创建新版本，不删除中间历史。

### CX-07 画面卡与执行清单 Schema — Codex

交付：

- 画面卡：目的、对象、场景、人物/设备/材料、景别、机位、构图、光线、色调、动作、科学信息、优先级、风险和参考图。
- 执行清单：未拍、已拍、需补拍、备注、文件编号和临时新增。
- 字段级验证与风险阻断规则。

验收：

- 至少一张必拍画面卡才能标记方案可执行。
- 每张卡必须回答“拍什么、为什么拍、怎么拍、有什么风险”。
- 结构化数据可用于网页展示、PDF/Word 导出和摄影现场执行清单，不需要分别解析 Markdown。

### DS-05 方案编辑器与版本面板 — DeepSeek

前置：CX-06 与 CX-07 API/Schema 已冻结。

交付：

- 分段编辑器、自动保存状态、未保存提示和冲突提示。
- 版本时间线、版本预览和恢复操作。
- 画面卡的新增、复制、排序、编辑和删除。

验收：

- 离开页面时，未保存内容会明确警告。
- 网络中断后不显示假的“已保存”。
- 画面卡排序和内容刷新后保留。
- 所有字段都能用键盘访问，错误定位到具体字段。

### DS-06 摄影现场执行清单 UI — DeepSeek

前置：CX-07 API 契约已冻结。

交付：

- 按场景和优先级分组。
- 现场一键标记已拍/需补拍，填写文件编号和备注。
- 离线或弱网状态至少保留未提交输入，不承诺本轮完整 PWA。

验收：

- 375px 宽度下可单手完成核心操作。
- 连续快速点击不会生成重复状态更新。
- 弱网或请求失败时，用户能看到未同步状态。

## M5 审核与导出（P0）

目标：方案可发给科研人员确认，并生成正式交付文件。

### CX-08 外部审核链接与权限 — Codex

交付：

- 限时、可撤销、仅存储哈希的审核 Token。
- 审核人无需注册，但只能查看被分享的项目摘要、事实、风险和可拍条件。
- 确认、修改建议、留言和审计记录。

验收：

- Token 过期、撤销或被篡改后无法访问。
- 审核页不暴露原始文件地址、用户其他项目、Clerk ID 或内部提示词。
- 审核结果不直接覆盖方案，而是生成待处理变更。

### CX-09 PDF/Word 导出管道 — Codex

交付：

- 同一结构化方案生成 PDF 和 DOCX。
- 包含封面、目标、诊断、对标案例、策展策略、画面卡、执行清单、待确认与来源。
- 导出任务在后台运行，文件保存到私有 OSS。

验收：

- 中文字体不缺字，图片不拉伸，表格不越界，长内容正常分页。
- PDF 与 DOCX 内容字段一致，不依赖分别维护两套业务数据。
- 导出链接有效期且不可访问他人文件。
- 至少用 3 份不同长度真实方案进行视觉验收。

### DS-07 外部审核页 UI — DeepSeek

前置：CX-08 API 契约已冻结。

交付：

- 无需登录的手机优先审核页。
- 对每个事实/风险执行确认、建议修改或留言。
- 过期、撤销、已提交和网络失败状态。

验收：

- 审核人在 10 分钟内能完成一次 10–20 项确认。
- 页面不需要理解 Agent、Schema 或工作流等技术词汇。
- 提交前显示未处理项数，提交后防止重复提交。

### DS-08 方案预览与导出 UI — DeepSeek

前置：CX-09 API 契约已冻结。

交付：

- 网页方案预览、PDF/Word 导出按钮、生成中、失败和完成状态。
- 导出前提示未解决审核项和缺失画面卡。

验收：

- 重复点击不会创建重复导出任务。
- 导出失败时保留用户方案，不重载整个页面。
- 预览内容顺序与导出文件一致。

## M6 内测运营与稳定性（P0）

目标：问题可被发现、定位、恢复，不需要依赖用户截图猜测。

### CX-10 安全加固 — Codex

交付：

- 网页抓取拒绝 localhost、私有 IP、云元数据地址和重定向后内网地址。
- 文件真实类型、大小、解压限制、超时和可选恶意文件扫描。
- 未完成上传、孤立 OSS 对象和过期导出文件的清理任务。

验收：

- SSRF 测试覆盖 IPv4、IPv6、DNS 解析、30x 重定向和云元数据地址。
- 恶意或损坏文件不导致 Worker 崩溃或无限内存占用。
- 清理任务仅删除可证明已过期的对象，具有 dry-run 模式。

### CX-11 监控、备份与压力测试 — Codex

交付：

- 健康检查、结构化日志、错误聚合、队列积压、模型失败率和存储告警。
- PostgreSQL 和 OSS 自动备份策略及恢复演练。
- 可配置的 20/50/100 虚拟用户压力测试，20 不是产品上限。

验收：

- 单个 Agent 失败可通过 request ID/job ID 定位。
- 模型或 Case Hub 不可用时，服务仍可登录、查看项目和编辑已有产物。
- 完成一次从备份恢复到隔离环境的演练。
- 20 虚拟用户完成核心流程时无数据串号、任务丢失或服务崩溃；50/100 用于观察扩容点。

### CX-12 管理员 API 与权限 — Codex

交付：

- 管理员角色判定和服务端强制权限。
- 用户、项目数、资料用量、AI 用量、失败任务、反馈和手动补额度 API。
- 补额度、重试任务和禁用账号操作写入审计日志。

验收：

- 普通用户在前端隐藏按钮后，直接请求管理 API 仍返回 403。
- 所有额度修改都有操作人、原因、变更前后值和时间。
- 管理员不能在默认列表中看到用户原始资料内容。

### DS-09 管理后台 UI — DeepSeek

前置：CX-12 API 契约已冻结。

交付：

- 用户与项目统计、配额用量、失败任务和反馈列表。
- 手动补额度和重试失败任务，必须填写原因。
- 搜索、筛选、分页、加载、空状态和错误状态。

验收：

- 表格数据与 API 一致，不在前端自行推算计费/配额结果。
- 高风险操作有二次确认和结果回执。
- 无管理员权限时不渲染后台内容。

### DS-10 用户反馈、FAQ 与内测教程 — DeepSeek

交付：

- 页内反馈入口：问题、建议、结果不准和其他。
- 自动携带页面、项目 ID、节点 ID 和 request ID，不自动携带资料原文。
- 内测 FAQ、首次使用指引和常见错误说明。

验收：

- 用户可在 30 秒内提交一条有定位信息的反馈。
- 额度用完、OCR 失败、网页抓取失败、Agent 超时和导出失败都有对应说明。
- FAQ 不包含管理密钥、内部接口和用户隐私数据。

## 5. DeepSeek 通用任务模板

验收标准：[从工作总表复制]
必须运行：npm run check、npm test，以及与任务相关的测试
交付时说明：修改文件、测试结果、未解决问题和人工验收步骤
不得提交、推送、部署或修改生产数据，除非用户另行授权。

## 6. DeepSeek 交付后的 Codex 验收流程

1. 确认 DeepSeek 只修改允许范围内的文件。
2. 检查是否重复业务逻辑、在前端伪造数据或绕过服务端权限。
3. 执行类型检查、全部单元测试和生产构建。
4. 执行该任务的验收用例和至少一条失败路径。
5. UI 任务在 1440px 和 375px 下进行浏览器验收。
6. 发现权限、数据丢失、并发、配额或安全问题时，不让 DeepSeek 继续扩大修改，改由 Codex 处理。
7. Codex 确认验收通过后，才可进入下一任务。

## 7. 全局 Definition of Done

每个任务必须同时满足：

- 交付物完整，没有 TODO、伪接口或未说明的 Mock。
- 类型检查、相关单元测试和生产构建通过。
- 至少验证成功、空数据、无权限、配额不足、网络失败和重复提交中与任务相关的路径。
- 新增 API 校验用户和项目归属。
- 错误信息告诉用户发生了什么、是否可重试、下一步怎么做。
- 新增配额和并发上限使用环境变量或数据库配置，不写死内测人数。
- 不在日志、前端、Git 或导出文件中泄露密钥、Token 和其他用户的私有资料。
- 相关 README、环境变量模板和运维说明同步更新。
