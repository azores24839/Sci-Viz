## 2. 分工原则

### DeepSeek（DS）负责

适合机械性强、边界清楚、容易通过测试确认的整理工作：

- CSS 去重与按功能拆分
- 已确认无引用的旧代码清理
- 大型展示组件拆分
- 依赖使用情况审计

### Codex（CX）负责

涉及核心状态、数据安全或公共接口边界的工作：

- Studio 页面核心逻辑拆分
- 保存状态与失败恢复
- API 错误处理约定
- 共享契约拆分与兼容
- 审核 DS 每批交付，避免误删或行为变化

## 4. DeepSeek 工作单

### DS-M01：CSS 去重与拆分

#### 任务

- 删除 `apps/web/src/styles/studio.css` 中重复的 Agent Job 样式。
- 按现有功能边界拆成 5–7 个 CSS 文件。
- 保持选择器、显示效果、响应式行为和组件逻辑不变。
- 不进行新的视觉设计。

#### 禁止修改

- React 组件逻辑和页面文案
- 服务端 API、数据库、权限和配额
- 共享 Schema
- 颜色、间距、字号和交互行为

#### 验收标准

- 重复的 Agent Job 样式只保留一份。
- `studio.css` 行数明显下降。
- 新文件数量控制在 5–7 个，不拆成大量零碎文件。
- `check`、`test`、`build` 全部通过。
- 报告新增/修改文件、删除的重复样式和验证结果。

#### 可直接发送给 DS 的指令

> 只执行 DS-M01：CSS 去重与拆分，完成后停止，不要开始其他任务。保持页面视觉和组件逻辑完全不变。删除 `apps/web/src/styles/studio.css` 中重复的 Agent Job 样式，并按现有功能边界拆为 5–7 个 CSS 文件，不要创建大量零碎文件。不得修改 API、数据库、权限、配额、共享 Schema、React 组件逻辑或文案。完成后运行 check、test、build，并报告修改文件、删除的重复样式和验证结果。

### DS-M02：清理无用演示代码

#### 任务

- 检查 Studio 和工作流节点中遗留的模拟案例、静态 Agent 结果、旧图表和演示分支。
- 只删除能够证明已无引用、且已被真实 Case Hub 或 Agent 数据替代的代码。
- 不删除空状态、错误状态和真实数据不可用时仍需要的降级界面。

#### 禁止修改

- Agent 任务状态机
- Case Hub 请求和数据结构
- API、数据库和共享 Schema

- `check`、`test`、`build` 全部通过。
- 如果无法确认某段代码是否仍有用途，保留并写入报告。

#### 可直接发送给 DS 的指令

> 只执行 DS-M02：清理无用演示代码，完成后停止。检查 Studio 与工作流节点中的模拟案例、静态 Agent 结果、旧图表和演示分支；只删除能证明已经无引用、且已被真实 Case Hub 或 Agent 数据替代的内容。不得修改 Agent 状态机、Case Hub 数据流程、API、数据库、权限、配额和共享 Schema；不得删除仍用于空状态、错误状态或降级显示的内容。完成后运行 check、test、build，并逐项报告删除内容、文件位置和判断依据。无法确认的代码必须保留。

### DS-M04：依赖清理审计

#### 任务

- 检查未使用、重复、异常或仅由安装环境产生的依赖。
- 特别检查 React Query 是否实际使用，以及 `npm ls` 中的 extraneous 包来源。

#### 验收标准

报告分为三类：

1. 可以安全删除，并提供代码搜索依据。
2. 应当保留，并说明使用位置或间接用途。
3. 需要 Codex 确认，说明风险和验证办法。

#### 可直接发送给 DS 的指令

> 只执行 DS-M04：依赖清理审计，完成后停止。本任务只允许输出报告，不得修改任何 `package.json`、lockfile 或依赖版本。检查未使用、重复、异常及 extraneous 依赖，重点确认 React Query 的实际使用情况和 extraneous 包的来源。报告必须分为“可安全删除 / 应当保留 / 需要 Codex 确认”三类，并为每项提供搜索依据、使用位置或风险说明。

## 5. Codex 工作单

### CX-M01：拆分 Studio 核心逻辑

- 从 `Studio.tsx` 提取工作流读取、保存和 Agent 后台任务协调逻辑。
- 页面继续负责组合界面和连接功能，不引入新的全局状态框架。
- 优先形成 2–3 个职责完整的 hook，不追求极端拆分。

验收：Studio 页面职责清楚；Agent 执行、页面刷新恢复和工作流保存行为不变；完整检查通过。

### CX-M02：完善保存状态和失败恢复

- 显示“保存中、已保存、保存失败”。
- 保存失败时保留本地修改并允许重试。
- 存在未保存内容时，离开页面前给予提醒。
- 避免频繁保存造成提示闪烁。

验收：用户不会在保存失败时误以为已经保存；错误可恢复；不改变正常保存的数据格式。

### CX-M03：统一必要的 API 错误处理

- 整理公共的响应解析与错误信息格式。
- 优先覆盖 Studio、方案、审核和 Agent 任务。
- 不进行全项目 React Query 迁移。

验收：常见的网络失败、权限失败和版本冲突具有一致、可读的提示；旧接口保持兼容。

### CX-M04：轻量拆分共享契约

- 将共享契约按来源、工作流、Agent、方案和审核分为领域文件。
- 保留统一出口，避免现有调用方一次性大范围修改。
- 不改变 Schema 字段、验证规则和 API 返回格式。

验收：现有导入方式兼容；契约更容易定位；完整检查通过。

## 6. 全局禁止项

本轮不做以下事项：

- 不引入 Redux、事件总线、微服务或插件系统。
- 不整体迁移到新的请求或状态管理框架。
- 不重写数据库仓库层。
- 不顺手修改产品功能、文案或视觉设计。
- 不为了减少行数而制造大量小文件。
- 不删除无法确认用途的代码或依赖。
- 不把本轮维护扩大为性能重构。

## 7. 最终验收

全部任务完成后，由 Codex 统一执行：

1. 全仓类型检查。
2. 全仓自动测试。
3. 生产构建。
4. Studio 核心流程浏览器回归。
5. 对比维护前后的大文件规模、重复样式和依赖报告。
6. 确认没有 API、数据库、Schema、权限和配额变化。

完成标准不是“文件越多越专业”，而是：现有功能不变，核心代码更容易定位，保存失败更容易发现，后续新增功能不必继续堆进同一个大文件。
