# Sci AI Studio Clerk 测试用户认证设计

> 日期：2026-07-02  
> 状态：产品方向已确认，待实施  
> 适用范围：约 20–50 名外部测试用户

## 1. 目标

允许测试用户使用邮箱和密码自行注册、验证邮箱、登录、退出和重置密码。所有 Studio 项目、上传资料、解析结果和 AI 用量必须归属于已认证用户，用户之间不能互相查看、修改或删除数据。

首版使用 Clerk 托管身份认证，业务 API、PostgreSQL、OSS 文件和 Qwen 调用继续运行在阿里云。Clerk 只负责身份，不保存科研资料正文或上传文件。

## 2. 选择 Clerk 的原因

- 提供现成的邮箱密码注册、邮箱验证、登录、退出、会话续期和密码重置。
- 前端组件和后端 JWT 验证成熟，减少自行处理密码安全的风险。
- 20–50 名测试用户在当前免费额度内。
- 不要求使用 Vercel；现有 React 前端仍可部署在阿里云。
- Clerk 若在中国大陆实测不稳定，身份层可替换，业务数据不需要迁移。

Supabase Auth 暂不采用：现有 PostgreSQL 与对象存储已经确定部署在阿里云，引入 Supabase 只做身份会增加跨云依赖；其默认测试邮件服务也不适合多人集中注册。自建密码认证暂不采用，因为密码存储、邮件验证和重置流程会显著增加安全责任。

## 3. 用户流程

```text
访问 Studio
  → 未登录：显示登录 / 注册页
  → 邮箱 + 密码注册
  → Clerk 发送验证邮件
  → 验证后进入 Studio
  → 后端自动创建该用户的默认示例项目
  → 用户上传和解析自己的资料
  → 退出或会话过期后返回登录页
```

用户可使用“忘记密码”完成重置。测试阶段不开放社交登录、手机号登录、组织空间和管理员角色。

## 4. 前端设计

- 根应用由 `ClerkProvider` 包裹。
- 未登录用户只能看到品牌化登录/注册界面。
- 登录、注册、邮箱验证和密码重置使用 Clerk 官方组件，并应用 Studio 黑、白、蓝视觉 token。
- 登录用户在顶部项目栏看到邮箱和用户菜单，可退出登录。
- 前端通过 Clerk 获取短期会话 token，并在每次 API 请求中发送 `Authorization: Bearer <token>`。
- 不再使用 `localStorage` 随机项目 ID 作为身份或授权依据。
- 项目 ID 可由前端用于路由和选择，但后端必须再次验证项目所有权。

登录页只承担身份入口，不承载营销内容。错误文案使用清晰中文，例如“邮箱尚未验证”“密码不正确”“登录状态已过期，请重新登录”。

## 5. 后端认证

- Server 使用 Clerk 官方后端 SDK 验证 JWT 的签名、签发者、有效期和用户 ID。
- 除健康检查和必要的公开配置外，`/api/v1/*` 默认要求登录。
- 验证成功后，将 `userId` 写入请求上下文；业务路由不得从请求正文接受 `ownerUserId`。
- 开发环境允许显式启用 `AUTH_MODE=mock`，使用固定开发用户；生产环境禁止在缺少 Clerk 配置时启动为公开服务。
- 日志只记录 Clerk user ID 或内部匿名标识，不记录 token、密码或完整 Authorization 头。

## 6. 数据所有权

新增项目所有权：

- `studio_project.id`
- `studio_project.owner_user_id`
- `studio_project.name`
- `studio_project.created_at`
- `studio_project.updated_at`

资料表继续包含 `project_id`，但所有资料查询必须通过项目表验证 `owner_user_id = 当前 Clerk userId`。禁止仅凭随机项目 ID 返回资料。

对象存储键采用：

```text
users/{ownerUserId}/projects/{projectId}/sources/{sourceId}/original.ext
```

服务端只为当前用户拥有的对象签发短期上传和预览 URL。删除资料时再次验证所有权。

首次登录时，系统为用户创建一个独立的“长兴海洋实验室”示例项目；后续可扩展为项目列表和新建项目。

## 7. 测试期额度

默认额度通过环境变量配置，后端强制执行：

- 每位用户最多 3 个项目。
- 每个项目最多 50 份资料。
- 每位用户总文件存储最多 500 MB。
- 单文件最大 50 MB。
- 每位用户每天最多 50 次 AI 任务，包括 OCR、摘要和 Agent 草案。
- 每位用户同时最多 2 个解析任务。
- 全局 Worker 并发默认 4，可根据 Qwen 额度调整。

达到额度时不删除已有数据，返回当前用量、上限和下一步建议。AI 调用在入队前预扣额度，失败且确认未调用模型时可返还。

## 8. 限流

API 同时按用户和 IP 限流：

- 普通读取：每用户每分钟 120 次。
- 创建、修改和删除：每用户每分钟 30 次。
- 登录后的上传签名：每用户每分钟 10 次。
- AI 任务创建：每用户每分钟 5 次。
- 未认证公开端点：每 IP 每分钟 30 次。

首版单 ECS 可使用进程内限流；当 API 扩展到多个实例时切换 Redis 共享限流。用户配额必须持久化，不能只存在进程内存。

## 9. Clerk 与阿里云边界

Clerk 保存：邮箱、认证状态和会话身份信息。

阿里云保存：项目、资料元数据、原文件、解析正文、OCR、AI 摘要、用量和审计记录。

Qwen 接收：完成 OCR、摘要或 Agent 任务所需的最小资料内容。

界面首次使用时明确说明上述数据流。隐私说明不得宣称所有处理都在本地或都在阿里云，因为身份验证经过 Clerk，AI 处理经过配置的模型提供商。

## 10. 配置

Web：

- `VITE_CLERK_PUBLISHABLE_KEY`

Server：

- `CLERK_SECRET_KEY`
- `CLERK_PUBLISHABLE_KEY` 或 Clerk JWT 验证所需配置
- `AUTH_MODE=clerk | mock`
- 用户、项目、存储和 AI 默认额度
- 各 API 限流参数

可发布的 Clerk key 可以进入前端构建环境；Secret Key 只能存在于服务端或部署平台 Secret 中。

## 11. 错误处理

- 无 token：`401 AUTH_REQUIRED`。
- token 失效：`401 AUTH_SESSION_EXPIRED`。
- 无项目权限：统一返回 `404 PROJECT_NOT_FOUND`，避免泄露项目是否存在。
- 用户额度已满：`429 USER_QUOTA_EXCEEDED`。
- 请求过快：`429 RATE_LIMITED`，返回可重试时间。
- Clerk 暂时不可用：已有有效 token 按 SDK 验证策略处理；不能静默降级到匿名用户。

前端遇到 401 时刷新 Clerk 会话一次；仍失败则回到登录页。遇到 429 时保留用户表单和已选文件，不要求重新填写。

## 12. 安全要求

- 后端所有资料路由执行所有权检查，不能依赖前端隐藏按钮。
- OSS Bucket 保持私有，只使用短期签名 URL。
- 上传完成后校验真实 MIME、大小和内容哈希。
- CORS 只允许正式域名和明确的本地开发域名。
- Clerk Webhook 需要签名验证；首版若不需要同步用户资料则不引入 Webhook。
- 密钥不得进入 Git、前端 bundle、错误响应或日志。
- 删除 Clerk 用户不会立即自动删除科研资料；测试阶段由管理员执行显式数据清理，避免误删。

## 13. 测试与验收

自动测试：

- 无 token、假 token、过期 token和有效 token。
- 用户 A 不能读取、修改或删除用户 B 的项目和资料。
- 用户 A 不能为用户 B 的 OSS 路径获取签名 URL。
- 首次登录创建独立示例项目，重复登录不重复创建。
- 项目数、资料数、存储和每日 AI 配额。
- 用户/IP 限流及重试时间。
- 401、404、429 的前端状态与表单保留。

端到端验收：

1. 两个邮箱分别注册并完成验证。
2. 两人登录后看到各自独立的示例项目。
3. 用户 A 上传资料后，用户 B 不可见。
4. 刷新页面后登录和项目状态仍保持。
5. 退出登录后无法通过旧页面或直接 API 访问资料。
6. 达到模拟额度后系统拒绝新任务但保留已有资料。
7. 密码重置和重新登录成功。

正式邀请测试用户前，使用中国大陆常见网络环境实际检查 Clerk 注册、验证邮件、登录和会话续期的可用性。

## 14. 明确不做

- 社交登录、手机号登录和企业 SSO。
- 团队组织、成员邀请、角色权限和项目共享。
- 付费订阅和商业计费。
- 管理员后台和批量用户运营。
- 自建密码存储。

这些能力在测试反馈明确需要后再单独设计。
